1.5 Iterative Denoising with Euler Sampling

Looking at the three denoising techniques, we can see Euler integration is the best. The Gaussian blur denoising works pretty badly overall, and that makes sense since there's too much noise. When it blurs there's still going to be some of that noisy input accounted for in the blur.

Looking at the one-step denoiser, it works pretty well but you lose a lot of image detail, and it looks very wonky when starting from a very noisy input. This is because the one-step denoiser travels towards the average of the 'correct image' manifold. When there's a lot of noise, this manifold is very large since there's a lot that can be interpreted with more noise, so the average is a lot bigger and you're capturing incorrect images in your average.

The Euler denoising works the best because you're basically taking small steps towards the correct image, and the longer you have it run for the closer you get to your actual image.

2. Conditional Generation and Guidance

2.1 Classifier-Free Guidance (CFG)

Without guidance, the model is sort of doing the same thing as seen in the one-step denoiser where it's landing at the average of all possible correct images, giving us an ugly and muddled one.

CFG sort of makes the model commit to one image by multiplying the direction I'm heading towards by w (7) and travelling towards that. It also steers me closer to an actual image and not an average image (not averaged image but image in the middle of all plausible image) through subtracting by the unconditioned velocty.

This results in a much cleaner image but it costs us in diversity. All the images are nice, but they look the same and have the same structure. In 1.6 with the naive stepping, we got images where the people were put in different poses and different angles.

3.3 Visual Anagrams

The visual anagrams! I'm actually super happy with how they turned out, especially the dog and cat one. The way these are down is pretty simple. We calculate two CFG velocities, the first one we use the image upright and a prompt. Then we flip the image upside down and calcualte the CFG velocity with a second prompt. Once we get those two, we simply take the average and head towards that velocity.

3.4 Hybrid Images

Low-pass filter: Gaussian blur with kernel size 265 and σ = 16.

Hybrid images! These use sort of the same trick as the visual anagrams, but instead of flipping one image and averaging the two CFG velocities we do something else. We calculate two CFG velocities using two different prompts, then for our final velocity we just pass one through a low pass filter and one through a high pass filter, add them together and travel using that. 1.2.2 Out-of-Distribution Testing

It denoises pretty well but starts to fall apart when it gets too noisy, incorporating artifacts into the final image.

1.2.3 Denoising Pure Noise

We can see that even after 5 epochs, the denoised images still end up looking like blobs. If you notice closely, the blobs sort of look like the average between all the digits, and you'd be correct. The reason for this is because of our loss function. Because our loss function is the Mean Squared Error, it's trying to find the image that has the least error across all possible images. This image turns out to be the the picture that's the average of all the digits, which is this blob.

We can fix this by conditioning our model during the denoising process.

Part 2: Training a Flow Matching Model

2.2 Training the Time-Conditioned UNet

D = 64, batch size 64, Adam with initial learning rate 1e-2, exponential decay γ = 0.11/10, 10 epochs.

2.3 Sampling from the Time-Conditioned UNet

40 samples per checkpoint, 50 Euler steps, same seed for every grid.

We can see that simply conditioning on time is not enough. Running in to the same problem that we've continued to run into, the model is simply heading toward the average of all possible images, making another nonsensical blob. It doesn't know whether to make a 1, or 2, or 5 etc. So it tries to make all of them and ends up failing. Simply conditioning on time is not enough.

2.5 Training the Class-Conditioned UNet

D = 64, batch size 64, class dropout puncond = 0.1, 10 epochs. With scheduler: Adam starting at 1e-2, exponential decay γ = 0.11/10.

2.6 Sampling from the Class-Conditioned UNet

4 instances of each digit, 300 Euler steps, guidance scale γ = 5, same seed for every grid.

With the learning rate scheduler

Without the learning rate scheduler (lr = 1e-2)

First I removed the scheduler and kept the initial learning rate of 1e-2 for all 10 epochs, with everything else unchanged.

If you notice, you can see that without the scheduler and keeping the same learning rate, some random artifacts start to appear in the final image as we have more epochs. This doesn't make a lot of sense, by 10 epochs we should end in a clean image. This happens because our learning rate is too high. Every time we optimize, the weights move proportional to our learning rate, since our learning rate is sort of high, our weights keep jumping around and never settle. This causes these artifacts to spawn in.

If you think about it in terms of a loss landscape, it's like we're going around the minimum without actually settling on it, leading to these imperfections.

Removing the scheduler, attempt 2: constant lr = 1e-3

To compensate for losing the scheduler, I lowered the constant learning rate to 1e-3, the value the scheduler decays to by the end of training.

By lowering the training rate, our weights are actually able to settle on the minimum, making our end image more accurate and devoid of artifacts.
